# NetPeek 0.2.0 验收记录

## 构建与范围

本版完善端点筛选、带观察时间的复制，以及紧凑窗口布局。保持 Windows 原生 WPF / .NET Framework 4.8、普通用户权限和本地采样；进程身份校验、IPv4/IPv6 解码与历史归属规则未改变。

验收的最终 EXE 版本为 **0.2.0.0**，大小 **141,824 字节**，SHA256：

```text
FA298A05B78EBF5653E0C8D9E25F803488FA8BBC47AA3D227A0A997B3CAA64D5
```

所有下列产品验收均指向这一 EXE。便携包使用 `build.ps1 -Package -SkipBuild` 复用它，打包后核对内嵌 EXE、配置、对应源码与许可证。发布资产的校验和单独提供在 `SHA256SUMS.txt`，不将 ZIP 自身的校验和嵌入 ZIP。

### 三项改动的复核

- **端点筛选**：应用名/路径、完整 PID、地址/端口/协议与状态、时间范围作用于同一条端点；历史状态明确为最后观察状态。验证了历史 IP 不会借同应用的另一条当前 TCP 连接命中，清空筛选不会删除数据，后台采样不会重新展开用户已收起的结果。真实 DataGrid 的选中项和非零滚动位置经过多轮采样仍保持。
- **复制**：实际 IPv4/IPv6 回环连接的快捷复制、本地/远端菜单与完整记录均与独立预期比较；历史 UDP 不提供远端。菜单打开后等待新的采样，再选择完整复制，内容仍对应打开菜单时的观察。另验证实际右键路由、说明窗口 Escape 关闭和完整警告文本。数据只在内存中比较，不发表剪贴板内容。
- **紧凑布局**：720×480 实际窗口中搜索、时间筛选、单行警告、端点复制均可用；更小的模拟工作区至少保留 70 DIP 的列表高度，并验证可滚动到完整复制单元格。帮助与完整警告为非模态独立窗口，不占用主列表高度。

剪贴板检查是“产品入口 → 实际采样与控件路由 → 系统剪贴板”，并非外部物理鼠标/键盘注入。GUI 的一项未验证观察是搜索框焦点请求，不冒充完整 Ctrl+F 输入测试。详见 [剪贴板记录](evidence/clipboard-0.2.0.json) 和 [GUI 记录](evidence/gui-0.2.0.json)。

## 性能方法与门槛

基线采用 GitHub 已发布的 v0.1.1 便携包，先核对发布 ZIP 的 SHA256，再提取 EXE。基线 EXE SHA256 为 `7537C8091A60768D7BC42DBC240A7D0B7F7C531DA8105A5120B890AABF408842`。

两版使用同一个测试宿主二进制，宿主嵌入产品 DPI 清单。每个场景各 **3 轮 × 15 秒**：全应用总览、指定进程的 513 条受控回环端点详情、最小化后的同一详情。采样核对实际 HWND 可见/最小化状态，记录自然端点数量变化；受控端点数必须前后一致。展开计时均先显式预热，避免新版自动展开搜索结果造成冷/热比较混淆。

早期基线仍含较多回环测试后的 `TIME_WAIT` 记录，背景端点数与新版测量差异明显，因此没有采用它作为正式对照。最终使用残留消退后补测的基线；两版非同时测量，实际自然负载范围随结果公开。

回归门槛：各场景整机 CPU 增量不超过 **0.2 个百分点**，平均 private bytes 增量不超过 **10 MiB 与基线 10% 中的较大者**。这些是工程回归预算，不是任何机器的资源上限。数值和负载范围见 [性能对照](evidence/performance-0.2.0.json)，门槛判定见验证汇总。

实测环境为 Windows 11 22631、Ryzen 7 9700X、16 个逻辑处理器。三场景均通过预算，窗口状态无无效样本需要剔除，受控端点始终为 513 条。

| 场景 | v0.1.1 平均整机 CPU | v0.2.0 平均整机 CPU | v0.1.1 平均 private bytes | v0.2.0 平均 private bytes |
| --- | --- | --- | --- | --- |
| 全应用总览 | 0.0445% | 0.0339% | 104.07 MiB | 106.14 MiB |
| 513 条端点详情 | 0.0085% | 0.0339% | 116.09 MiB | 113.90 MiB |
| 最小化后台 | 0.0360% | 0.0487% | 119.03 MiB | 118.84 MiB |

预热后的三次展开平均耗时为 **5.43 → 5.46 ms**。最大平均 CPU 增量约 0.0254 个百分点，最大平均 private bytes 增量约 2.07 MiB；本轮未观察到超出预算的性能退化。不要把小幅波动解释为确定的性能提升或损耗，尤其后台场景的自然端点范围仍有差异。

独立合成负载包含 40 个应用、4,000 条当前端点和 12,000 条历史端点，循环切换全部/历史/当前/无结果查询 48 次。最终 EXE 的筛选处理 P95 为 **7.04 ms**，最大 **7.11 ms**，通过 100 ms 门槛。这只计算显示集合投影，不包含 140 ms 搜索防抖、WPF 渲染或系统采样。见 [筛选性能](evidence/filter-performance-0.2.0.json)。

512 条不变端点的差量通知探针对比两版均为零属性/集合通知，精确最后观察时间仍推进，未知身份仍保持明确不确定性。见 [刷新回归](evidence/refresh-0.2.0.json)。

## 本轮验证修正

- 修复集成脚本把 PowerShell 7 自动反序列化的 `DateTime` 再经地区格式字符串解析的问题；5.1 字符串与 7 日期对象分开处理，并明确成功退出码。
- 剪贴板测试在产品窗口就绪后保存原格式，等待实际复制结果而非固定延时；恢复发生在窗口关闭前，并核对实际数据。若剪贴板已被外部修改，则保留新内容。
- 对齐程序集与 Win32 清单版本；测试宿主使用产品 DPI 清单。较早的未对齐宿主采样及失败的测试准备尝试保留在本地，但不作为本版最终性能或验收证据。

最终产品源码复核与上述测试没有复现新增功能回归。原始进程信息、端点表、截图及失败诊断只保存在 Git 忽略的 `artifacts/v0.2.0/`；公开记录只保留必要的计数、方法、结果和二进制指纹。

## 未验证边界

未覆盖 Windows 10 跨机、真实高 DPI/多屏切换、网卡切换、睡眠唤醒、全量物理键盘导航、屏幕阅读器及所有剪贴板管理器。资源数据包含相同测试宿主与采样器的开销，不能当作独立 EXE 绝对占用；自然系统负载变化也限制了微小差异的解释。没有执行外网连接探测或修改显示/安全设置。应用仍未签名。
