最终 EXE 为 **0.3.0.0**，**146,432 字节**，SHA256：

## 性能回归与修复过程

基线来自已发布且 ZIP 校验和匹配的 v0.2.0，EXE SHA256 为 `FA298A05B78EBF5653E0C8D9E25F803488FA8BBC47AA3D227A0A997B3CAA64D5`。两版使用同一测量宿主、同机环境、每场景三次十秒采样，513 条受控真实回环端点始终一致。场景为总览、展开受控进程和最小化后台；保留样本的自身 HWND 可见／最小化状态全部符合预期。

初始候选在正序、逆序对照中均出现前台 CPU 增量超标。隔离构建保留新 C# 逻辑，先换回旧 XAML、再仅恢复原先简短搜索占位提示，短诊断均未复现高 CPU。最终版本保留简短占位提示，精确查询示例仍在悬浮说明、辅助功能说明和帮助中。底层 WPF／渲染机制未做堆栈采样，不能把这一观察表述为已证明的底层根因。失败轮次和诊断保留在[调查汇总](evidence/performance-investigation-0.3.0.json)，逆序原始汇总见[修复前逆序对照](evidence/performance-0.3.0-reverse.json)；这些不是发布 EXE 的验收结果。

修复后的最终 EXE 独立完成完整复验，与最近一轮 v0.2.0 基线比较如下：

| 场景 | v0.2.0 整机 CPU | v0.3.0 整机 CPU | v0.2.0 平均 private bytes | v0.3.0 平均 private bytes |
| --- | --- | --- | --- | --- |
| 总览 | 0.1145% | 0.0350% | 110.51 MiB | 107.68 MiB |
| 展开详情 | 0.0955% | 0.0987% | 115.92 MiB | 113.45 MiB |
| 最小化后台 | 0.0254% | 0.0223% | 119.21 MiB | 119.91 MiB |

沿用原回归预算：每场景整机 CPU 增量 ≤ **0.2 个百分点**，平均 private bytes 增量 ≤ **10 MiB 与基线 10% 中较大者**；三场景全部通过。预热展开三次平均 7.75 → 6.97 ms。数字包含宿主和采样开销，不是独立 EXE 的资源占用；展开时间不是鼠标到显示的延迟。

自然系统负载并不相同：总览基线／最终自然端点范围分别为 603–809／365–385，展开为 530–592／363–383，后台为 400–535／384–484。因此这些结果支持本轮预算检查，不能据此宣称性能提升，也不保证其他机器或负载下没有回归。完整方法和计数见[最终性能对照](evidence/performance-0.3.0.json)。

独立合成筛选负载为 40 个应用、4,000 条当前及 12,000 条历史端点，48 次切换全部／历史／当前／无结果查询；P95 **6.97 ms**、最大 **7.00 ms**，通过 100 ms 门槛。此项不包含防抖、WPF 渲染或系统采样，也不单独测量精确查询语法。[筛选记录](evidence/filter-performance-0.3.0.json)

512 条不变端点的两版对照均产生零属性／集合通知，最后观察时间准确推进，未知身份仍保持不确定性。[刷新记录](evidence/refresh-0.3.0.json)

## 覆盖边界

- 实际窗口为 96 DPI；高 DPI 工作区换算和紧凑尺寸另有模拟检查。Windows 10、实际高 DPI／多屏切换、睡眠恢复、网卡变化、完整外部键盘和屏幕阅读器验收仍未覆盖。
- 没有执行外部网络探测，没有改变防火墙、系统权限、依赖或采集协议。
- 仓库没有 GitHub Actions 工作流；本次依据本地最终 EXE 验证和发布资产核对，不声称 CI 通过。
- 原始端点、进程、截图、故障报告和隔离构建只保存在 Git 忽略的 `artifacts/v0.3.0/` 与 `tests/bin/`。公开记录保留方法、计数、结果及必要指纹，不包含私人连接表或剪贴板内容。
