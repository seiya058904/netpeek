# NetPeek 0.1.0 验证记录与复测方法

本文件保留首版记录；当前版本见 [0.1.1 验收报告](VALIDATION_0.1.1.md)。

本文区分自动化结果、实际主机覆盖范围和未验证场景。生成的 JSON 是实测证据；脚本存在本身不代表测试通过。

下方原始 JSON 链接指向本机开发工作目录中的 `artifacts/`，仅在该本地目录中可用。这些文件包含本机应用路径和端点，不提交到 GitHub，也不随便携包或源码 ZIP 分发；结果汇总和复测脚本保留在仓库和交付包中。

## 验证命令

在普通权限 Windows PowerShell 5.1 中，从仓库根目录执行：

```powershell
.\build.ps1
.\tests\run-core-tests.ps1
.\tests\run-viewmodel-tests.ps1
.\tests\IntegrationTests.ps1
.\scripts\Measure-NetPeek.ps1
```

集成测试默认只读取现有连接表、执行 NetPeek 快照和 GUI smoke，不创建测试套接字、监听端口或测试子进程。先后读取两次 Windows 系统表，用中间的 NetPeek 快照核对前后保持相同五元组、PID 和状态的端点；每个协议分别记录 IPv4/IPv6 实际匹配数。某个地址族匹配数为零不能宣称该地址族已经验证。系统命令额外显示的 TCP `Bound` 项不属于原生 TCP 连接表，明确排除。

需要受控连接、压力连接、进程退出和外网探测时，显式运行：

```powershell
.\tests\IntegrationTests.ps1 -LiveSockets -ExternalHost github.com -ExternalPort 443
```

`-LiveSockets` 创建 96 对 IPv4 TCP 回环连接、8 对 IPv6 TCP 回环连接、两个 TCP 监听器和 IPv4/IPv6 UDP 端点。这些连接始终保持到核对结束，避免短连接采样时差造成错误结论，并运行监听子进程退出检查。测试使用交付目录中的真实可执行文件，不调用测试替身。`-ExternalHost` 独立控制外部探测；不带它就不会建立外部测试连接。

- 快照中的 TCP 五元组、PID、状态和 UDP 本地端点/PID，与同机 `Get-NetTCPConnection` / `Get-NetUDPEndpoint` 核对；不要求整个系统两个非同时快照逐行相等。
- TCP 监听端点的远端字段无意义，NetPeek 将其置空；UDP 本地绑定同样不伪造远端或互联网访问状态。
- 仅 `-LiveSockets`：子进程建立 TCP 监听后退出，再次采集必须移除该端点。
- `--smoke-test` 打开真实 WPF 窗口，5 秒后正常退出；测试观察应用进程树并检查已观察到的子进程是否存活。
- 默认测试不绑定套接字。`-LiveSockets` 仅绑定回环。指定 `-ExternalHost` 时另外建立并保持一条真实外部 TCP 连接，核对远端、端口、PID 和状态，保存系统侧证据；它只建立 TCP 连接，不下载内容。外部连接失败会明确使本轮测试失败，不会静默跳过。
- 测试不会切换网卡、修改代理、VPN、防火墙或关闭其他进程。失败清理只处理此测试创建的进程和套接字。
- `-SkipGuiSmoke` 仅用于避免与人工界面检查互相抢焦点；使用该参数的报告会明确标记 GUI 检查跳过。正式交付应补跑完整测试。

证据在 `artifacts/integration/`，包含系统工具结果、各阶段快照和带检查项的结果 JSON。`Passed=false` 或脚本退出码非零都意味着验收失败；不得只看一部分 PASS 输出。

## 性能测量口径

`scripts/Measure-NetPeek.ps1` 先做一次未计入结果的预热启动，然后默认执行三次测量，每次前台 15 秒、最小化后台 15 秒。应用自己的 `--benchmark REPORT SECONDS` 模式负责激活窗口、定时最小化、报告阶段和自动退出；脚本只读取前台状态及性能计数，不发送窗口控制命令。测量时保持相同网络负载，不操作其他高负载应用；界面前台状态记录在每个样本中。如果窗口未取得前台，不能把对应样本宣称为完整前台测试。

| 指标 | 定义 |
| --- | --- |
| 启动 | 应用内 Stopwatch 从入口到首个 WPF `ContentRendered`；不包括 Windows 创建进程之前的时间 |
| 首次数据 | 同一 Stopwatch 到首次网络快照应用于界面；另列，避免将空窗口误认为可用数据 |
| CPU / 整机 | 观察到的完整进程树 CPU 秒增量 ÷ 真实采样秒数 ÷ 逻辑处理器数 × 100% |
| CPU / 单核 | 同一 CPU 秒增量 ÷ 真实采样秒数 × 100%；可超过 100% |
| 工作集 | 根进程和已发现子进程工作集之和；共享页可能重复计数，附平均与峰值 |
| 私有字节 | 同一进程树的 PrivateMemorySize64 之和；附平均与峰值 |
| 后台 | 最小化窗口，继续采集；不是关闭窗口，也不等同于托盘隐藏 |
| 退出 | 应用按测试模式自行定时退出，核对退出码及已发现子进程；`AutomaticExitWaitMilliseconds` 仅为采样后等待预定退出的时间，不是关闭耗时 |
| 包体 | 实际交付目录全部文件逻辑大小之和；同时列出每个文件 |
| 必要运行时 | .NET Framework 4.8 或更高版本，Windows 共享运行时，不打入应用目录；单独记录注册表版本和两处 Framework 目录实际大小 |

运行时目录大小不包括所有 GAC、原生映像缓存和 Windows 组件存储，也不抵扣硬链接；因此它是范围明确的共享运行时磁盘实测，不是 .NET 增量安装空间。不能把应用包体称为包含全部运行时的大小。

约一秒一次的进程树采样可能漏掉生命周期不足一个采样周期的子进程。CPU 只累计相邻样本中身份一致（PID 与启动时间）的进程，原始样本保留于 `artifacts/performance/`。NetPeek 的目标架构没有采集辅助子进程；是否实际观察到子进程仍以报告为准。

同机前后比较必须分别运行真实可执行的旧版与新版，统一启动口径、采样时间和网络负载。此脚本要求 NetPeek 的 `--benchmark` 接口，不能未经适配直接用于 Snitch。没有成功运行旧版时，应将旧版列为“未实测”，不得将仓库源码大小、依赖声明、理论估算或其他机器结果填成基线，也不得声称提升百分比。

## 实际覆盖与限制

| 场景 | 验证方式 / 当前证据要求 |
| --- | --- |
| 普通权限原生采集 | 集成脚本检查当前权限并验证四种网络表；必须在非提权会话运行 |
| IPv4/IPv6 TCP、UDP 与高连接量 | 默认只比较稳定现有端点；高连接量及受控四种端点需显式 `-LiveSockets` |
| 出站网络连接 | 通过 `-ExternalHost` 实测时保存本机实际可见元组；代理/Fake-IP 环境不能据此推断最终服务器 IP 或绕过代理直连 |
| 进程退出 | `-LiveSockets` 下子进程关闭前后快照核对；默认模式不覆盖该项 |
| 失败与恢复 | 核心测试可注入采集失败；生产采集失败的系统条件不能由普通成功快照代替证明 |
| PID 实际重用 | 不通过大量创建进程强迫 PID 重用；核心身份单元测试与真实系统 PID 重用分开报告 |
| 短连接 | 轮询间隔内建立并结束的连接可能无法观察；不承诺完整连接历史或完整流量审计 |
| UDP 远端、逐应用传输量、访问域名 | 原生端点表无法可靠给出；不生成虚构速度、流量或域名 |
| 同名不同路径、多个进程 | 核心分组测试和可获取的进程路径/启动时间验证；受权限限制时需保留未知状态 |
| 暂停、恢复、筛选、焦点、滚动、托盘 | 真实 GUI 交互验证；5 秒 smoke 不替代完整交互验收 |
| VPN / 代理 | 需要具有对应配置的主机和稳定流量，检查显示的是本机可见端点；未配置或未实测时标注未验证 |
| 网卡切换 / 断网 / 休眠恢复 | 涉及用户会话和网络环境，不自动触发；需要专门会话验证 |
| Windows 10 / Windows 11 | 实测系统以性能报告 OS 字段为准，单一系统不能代表另一个系统已经通过 |
| 100% / 150% / 200% DPI | 需对应桌面 DPI 环境的真实截图与交互验证；缩放截图不能替代系统 DPI 测试 |
