验收边界：最终程序完成下表全部回归、真实连接核对和四轮 GUI smoke。较早的候选 EXE `F2D194843F15451CD01FB518268DAC2711526BF82D2C4A2C25749A5D54311720` 完成了完整交互、高 DPI 和三场景性能测试；之后只补上详情固定列的最小宽度。最终版本追加性能采样时出现非预期最小化，用户表示正在使用桌面并要求保留已测结果，因此停止追加可见窗口测试。下面分别标注证据所属二进制，**不把候选版完整验收冒充最终 EXE 全项通过**。

实机：Windows 11 企业版 22631，Ryzen 7 9700X、16 逻辑处理器，.NET Framework 4.8.09032（Release 533320），Windows PowerShell 5.1，非管理员。单屏 3840×2160、工作区 3840×2076，有效 DPI 168，即 **175%**；没有修改系统显示或安全设置。

## 真实连接和异常退出

```powershell
.\tests\IntegrationTests.ps1 -Executable .\dist\NetPeek\NetPeek.exe `
  -OutputDirectory .\artifacts\v0.1.1\final-integration-minwidth `
  -LiveSockets -StressConnections 256 -ExternalHost github.com
```

70 项全部通过。稳定系统端点核对覆盖 TCP IPv4 837 / IPv6 13、UDP IPv4 46 / IPv6 21，缺失 0。另建立 256 对 IPv4、8 对 IPv6 TCP 回环连接及两个 UDP 端点，核对元组/PID/状态，验证子进程正常退出后监听消失。外部 TCP 检查经过本机代理，只证明系统表可见的连接，不证明直连或网站真实服务器 IP。

每轮 GUI smoke 先写旧报告哨兵，再核验新 run ID、实际 PID、开始/写入时间、最终完成状态、退出码和已应用的完整快照：

| 场景 | 结果 |
| --- | --- |
| 正常真实采样 | 退出 0，最终 Success=true |
| 合法零端点完整快照 | 退出 0，确实应用过完整快照，不要求端点数大于零 |
| 写过有效快照报告后 UI 异常 | 退出 1，Success=false，旧报告不能使验收通过 |
| 始终采集失败 | 退出 2，Success=false，正常收尾不掩盖失败 |

四轮均未观察到遗留子进程。故障注入只由显式 `--smoke-test --test-fault` 开启；诊断失败不弹阻塞消息框，也不将注入错误写入日常异常日志。

## 交互、布局与截图

桌面自动化工具两个入口均因 `failed to write kernel assets` 无法初始化。本轮用测试进程加载相应实际 EXE、调用真实 `Program.Main`，在自身 WPF Dispatcher 操作实际绑定、控件事件和窗口，没有通过外部 UI Automation 绕过工具，也没有向交互/性能场景注入虚构应用行。这是同机真实 WPF 路径自动测试，不等同于人工鼠标/键盘验收。

[GUI 汇总](evidence/gui-0.1.1.json) 中的 **F2 候选版**验证搜索空态、Escape 路由、清空筛选、展开、剪贴板内容精确比对、暂停时间保持/恢复更新、托盘隐藏、第二个真实 EXE 退出 0 并唤回同窗、唯一程序退出超过 60 秒后移除，以及同路径新 PID 的实际图标重现。另以 8 个同路径真实进程检查分组和展开；未发现需要替换中间进程层的证据，保留 ItemsControl。最终 7537 EXE 没有重跑完整交互链。新增连续快照间选中项/滚动位置检查只编译通过，未实际运行；焦点和完整键盘导航也不能据此算通过。

曾有两轮在 65 秒检查时看见旧条目。增强诊断确认其中一轮窗口已经最小化，UI 最新快照只跨过最后观察时间 22.88 秒，同时完整系统快照已没有该程序端点。程序按设计最小化后不绘制。这是验收读取旧画面的误判：用例现恢复自身窗口，等待完整快照跨过保留期后再检查，有界等待；F2 的成功轮实际走过该恢复路径。保留原始失败和诊断，没有改变产品历史语义来迎合测试。

F2 在实际 **175%** 环境的 **720×480 DIP** 窗口中，暂停警告与说明同时展开：窗口 DPI=168、WPF 变换 1.75×1.75，列表仍有 **146.286 DIP**；详情表宽 494.857 DIP。[最小窗证据](evidence/minimum-window-0.1.1.json) 和[该轮图片](screenshots/0.1.1/pre-minwidth-minimum-window.png) 保留真实窗口值。随后截图复核发现，仅核验复制按钮在视口内还不够：固定列被星号列挤压时文字会裁切。因此最终版本为状态、复制、协议、范围、时间列增加明确 MinWidth，并通过 49 项离屏布局回归。最终版没有重跑真实高 DPI 最小窗口；没有测试运行期间 DPI 切换。

离屏布局另覆盖 1180×800、720×480、640×360、512×360 DIP；长警告与说明同时展开时列表最低 70.9 DIP。280 DIP 极窄详情视口会解除冻结列，横滚后复制按钮可达。200% 等换算用例属于数学模拟，不替代物理显示器覆盖。

## 性能方法与结果

完整对比属于 **0.1.0 与列宽修复前的 F2 候选版**，见 [performance-pre-minwidth-0.1.1.json](evidence/performance-pre-minwidth-0.1.1.json)。同机两版使用同一冻结宿主 `C2DEBE4307D8E430B157730895B97FBC4873B7C541D7BFADB3310F55B89BF10E`、实际加载各自 EXE。负载是一个真实进程的 256 对回环 TCP 连接和一个监听端点，合计 **513 个端点**。总览显示自然应用列表；详情先搜索固定 PID，仅展开该进程。每版本、每场景测 3 轮，每轮请求 15 秒，以实际采样时间归一化；每轮前后核验 513 个端点，各场景 48 个状态样本全部有效。

| 场景 | 平均工作集 MiB：旧 → F2 | 平均私有内存 MiB：旧 → F2 | 整机 CPU %：旧 → F2 |
| --- | --- | --- | --- |
| 总览 | 121.92 → 123.82 | 124.53 → 132.40 | 0.04369 → 0.05456 |
| 展开 513 端点 | 128.20 → 130.30 | 141.82 → 141.52 | 0.03565 → 0.05050 |
| 最小化后台 | 131.19 → 132.87 | 144.45 → 144.00 | 0.07352 → 0.06505 |

同一受控详情首次展开为 98.65 → 84.49 ms；两次热展开分别为 7.02 → 2.69、3.79 → 2.61 ms。通知量显著减少，但这组实测并不支持“所有场景 CPU 或内存下降”；自然应用和系统负载仍有波动，短时差值不能泛化为性能保证。

[最终 7537 EXE 的性能记录](evidence/performance-0.1.1.json) 只有总览第 1 轮有效：15.578 秒、16/16 个可见且非最小化样本，平均工作集约 119.53 MiB、私有内存约 125.87 MiB、整机 CPU 0.04388%。第 2 轮和唯一重试分别出现 10/16、2/16 个最小化样本，均排除；展开与后台未测。无法确定最小化来源，不能只根据正在使用桌面就归因于用户。此时用户要求保留已有数据，停止追加可见窗口测试。该轮负载已经用同一脚本重启为另一进程，仍在前后核验 513 端点。**最终程序没有完成三场景性能对比。**

测量包含相同宿主及进程内采样开销，统计完整已观察进程树的工作集和私有内存，不能当成裸 EXE 占用。机器 CPU 百分比除以 16，JSON 同时给单核百分比、峰值、自然端点波动范围和场景状态。展开响应是设置真实绑定、布局完成到 Dispatcher ContextIdle，不是鼠标到屏幕延迟。两版均保留虚拟化，新版更紧凑的行高在同一视口实现 8 行，旧版为 7 行。

0.1.0 与 F2 原生 EXE 的暖启动及总览/最小化记录单列于 [native-performance-0.1.1.json](evidence/native-performance-0.1.1.json)，不可与宿主结果混算。每版预热一次后测三次；前台焦点并非全程获得，报告记录实际样本数。最终 7537 未重跑原生性能，不能继承 F2 的数值。

较早的[全部自然应用展开试验](evidence/performance-all-apps-0.1.1.json) 生成了不同数量的详情表，不能把它的耗时直接归因为单进程布局优劣；保留该结果，用固定 513 端点作为主要对照。

## 复测与交付

```powershell
.\build.ps1
.\tests\run-core-tests.ps1
.\tests\run-core-tests.ps1 -Executable .\dist\NetPeek\NetPeek.exe
.\tests\run-viewmodel-tests.ps1 -Executable .\dist\NetPeek\NetPeek.exe
.\tests\run-icon-cache-tests.ps1 -Executable .\dist\NetPeek\NetPeek.exe
.\tests\run-layout-tests.ps1 -Executable .\dist\NetPeek\NetPeek.exe
.\tests\run-controller-state-tests.ps1 -Executable .\dist\NetPeek\NetPeek.exe
.\build.ps1 -Package -SkipBuild
```

`-Executable` 模式仅编译测试、引导器或反射适配器，业务代码来自指定 EXE；默认源码单测另行标识。打包使用 `-SkipBuild` 保持已测 EXE 不变，文件名版本从 AssemblyInfo 读取。`NetPeek_0.1.1_windows_x64.zip` 内含对应 `NetPeek_source.zip`，另交付 `NetPeek_0.1.1_source.zip`，包括构建脚本、测试、脱敏汇总、截图和许可证。

性能复测用 `tests/Start-EndpointLoad.ps1` 建立显式回环负载，将返回的 PID 传给 `tests/run-wpf-harness.ps1 -Mode benchmark -SampleSeconds 15 -Runs 3 -FixtureProcessId <PID>`；指定旧/新 EXE 与独立输出目录，再运行 `scripts/Compare-NetPeek.ps1`。fixture 用自身 stop 文件正常退出，不结束同名的其他进程。GUI 模式需可见桌面，会操作自己的窗口、剪贴板和焦点。

## 未验证范围

最终列宽补丁后的完整 GUI 交互链、真实高 DPI 最小窗、三场景与原生性能没有重新跑完；按用户要求保留已测结果收尾。Windows 10 跨机、多物理显示器、DPI 动态切换、网卡切换、完整断网与休眠/唤醒、所有 VPN 产品、外部物理鼠标/完整键盘导航及屏幕阅读器，也未完成本轮验收。应用未做代码签名。图标缓存按路径/容量管理，不保证同路径文件被替换后立即更新图标；显式 UNC 和映射网络盘守卫已检查，未对所有 reparse point 重定向组合做网络抓包证明。
